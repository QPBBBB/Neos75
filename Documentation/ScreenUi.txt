文档与显示架构
Code/Module/Screen/Utilities/MarkdownUtilities.py 使用 Mistune 3.3.4、Pillow 11.3.0 解析、排版和生成字形掩码。
字体使用 Windows 自带微软雅黑/Consolas，不随仓库分发字体文件。
WriteMarkdown.py 编译 NSMD 包，通过 HID 分块、节流、CRC32 校验后激活；只选择 5542:0001 屏幕接口。
Code/Module/Screen/Markdown/MarkdownDocument.c 在 UI 定时器中分配内存、处理上传、渲染和滚动。
文档由行索引、字形记录、字形引用和掩码组成；固定最多 24 个可见 label，每帧文字更新预算 24 KiB。
全文使用行号窗口，不依赖超出 16 位坐标范围的单个长 label。
单篇源文件最多 65536 字节，编译包最多 262144 字节；字形/图片位图最多 98304 字节、6400 个字形记录。
上传新文档前释放旧文档；失败后需重新上传，不提供旧/新文档同时保留的原子切换。
文档仅存 RAM，不写 Flash，断电后需重新上传；开机未上传时仍显示 NEOS75 UI/hellow world/Running。
修改开机初始画面通过 Device/ScreenUiConfiguration.json 重新构建；日常 MD 更新不刷固件。

原厂页面移除范围
不调用原厂 GUI 初始化，保留显示/USB/RTX/LVGL 与存储解码初始化，复用初始空白 screen。
原 GUI 七个页面指针均为零；不创建原厂页面对象，也不注册其页面专用刷新定时器。
原厂页面、菜单、主题、天气和时钟报文不进入原业务解释器。
V04 只额外处理已校验的旋转报文 A5 39，发送原协议确认，再把相对滚动交给 UI 线程。
启动调用原生 screen-ready(state=2) 通知，旋钮确认固定发往 UART port 1。
原始 DFU 服务与只读信息查询保留；底层二进制库、原始镜像和资源归档保留用于运行和恢复。
没有完整厂商 SDK，未将整片原厂固件/资源物理清空。

协议
外层 A5 41 帧：命令、两字节大端长度、载荷、原生求和异或校验，HID 报告体最多 64 字节。
selector 7F：只读 UI 状态，NSUI 版本 4，页面对象数、活动页面、设备定时器和保护状态。
selector 7D：只读最近控制帧，忽略周期 35 状态包，仅用于诊断控制事件，不记录 MD 正文。
selector 7E：MDUI 版本 1。
  0 状态，1 开始（总长度/CRC32/源文件长度），2 数据（严格递增偏移，每块最多 51 字节），3 提交，4 相对滚动。
  每次只允许一个操作排队；状态返回处理结果、会话、接收字节、活动状态、行号和源文件长度。
原信息长度门限由 ==1 改为 >=1；外层 hook 先限制 1..59 字节，再进入保留的原生校验路径。
不增加任意地址写入、解锁或启动器命令。
