NEOS75 固件定制调查
调查日期：2026-11-02（Asia/Shanghai）

结论
已完成实机只读协议验证、键位/旋钮配置导出、原厂固件获取和离线格式分析。
目前没有获得可编译的 NEOS75 原厂工程或 UB32 SDK，因此还没有可刷写的自定义固件。
现有证据足以把后续工作分为键盘逻辑固件、屏幕逻辑固件、屏幕图形资源三部分。

一、已由实机验证
1. 有线键盘：AULA-Neos75，VID:PID = 1EA7:4884。
   标准 Raw HID：usage page FF60，usage 0061，interface 1。
   serial_number = vial:f64c2b3c。
2. 设备回应 VIA 协议 12、Vial 协议 6，UID = 19331032a15430b0。
   内置定义名称为 "Venus 84 "，矩阵 7×15，3 个层，定义压缩后 1583 字节。
   已导出完整三层 keymap.bin；这不是整片 Flash 或用户宏的完整备份。
3. 标准 Vial GET_ENCODER（FE 03 layer index）可读取两个旋钮映射。
   index 0：
     layer 0：逆时针 00AA（音量减），顺时针 00A9（音量加）。
     layer 1/2：逆时针 7828（灯光亮度减），顺时针 7827（灯光亮度加）。
   index 1：全部三层逆时针 7E10（LCD mode-），顺时针 7E0F（LCD mode+）。
   本次没有发送 SET_ENCODER。读取成功证明接口存在，尚未实测写入、断电保存或无线继承。
   旋钮按压走普通矩阵键位；布局中的 e0/e1 是厂商标签，不能当作标准 Vial 编码器布局直接解析。
4. 屏幕独立 USB HID 设备：VID:PID = 5542:0001。
   官方屏幕代码独立连接这台设备；实机可回应 GET_DEVICE_INFO。
   当前返回 width=320、height=320、screen_type=0、JPEG 支持=true、WinUSB 支持=false。
   注意：这是协议回报值，未证明物理面板为 320×320。
   原厂云端资源包头标记 NEOS 480*360，存在不一致，不能直接拿它刷入后验证。

不能因为文件可离线改动、CRC 可计算，就认为修改后的固件一定会被设备接受。

三、架构判断及可行性
旋钮：已有设备侧映射接口，可先做配置验证；自定义按压/长按/加速/菜单逻辑需要修改主控程序。
键盘与屏幕：是独立 USB 身份和独立升级文件。键盘程序中的 SerialLcd 字符串提示存在串行控制链路，
但线路、电平、串口配置和键盘到屏幕的报文尚未通过硬件采集验证。
屏幕：已确认 LVGL 资源和屏幕 MCU 分开；全新页面/控件逻辑应在 MCU 工程或二进制中实现。
实时电脑数据：固件可自行渲染页面，但 CPU 温度、正在播放的歌曲等仍需电脑发送数据。
协议兼容 VIA/Vial 不等于存在可直接重编译的标准 QMK 工程；包内 RTX 线索说明需核对厂商实现。

   可询问是否提供满足相关开源组件许可证要求的源码；本次未判定具体许可证义务。
2. 明确屏幕 320×320 回报与 480×360 资源包头不一致的原因，并确认实机运行版本。
3. 没有源码时，对已取得的 ARM Thumb 固件离线反汇编：
   优先定位 encoder/Vial FE03、FE04 处理函数、屏幕切页动作与 SerialLcd 发送函数；
   屏幕侧定位 LVGL 初始化、页面事件、资源加载和 A5 41 命令处理。
4. 在恢复方式和 PCB 版本确认后，再制作单一可验证改动的测试镜像。
   本节记录初次只读调查时的状态；后续设备端接入与刷写见第六节。

六、设备端 UI 实际接入（2026-11-02 后续推进）
1. 取得并验签官网 https://app.aulacn.com/hero/UB32-Driver-Setup.exe。
   安装包签名有效，用户明确允许仅为屏幕 DFU 5542:1000 安装 WinUSB。
   原厂清单有多个型号，实际使用 ScreenDrivers.txt 单条清单，安装日志与结果在 Research/Driver。
2. 进入屏幕 DFU 后，确认设备名 UBEST DFU Screen Firmware Update，DfuSe 1.1a，传输块 4096 字节。
   内存描述符：@Internal Flash /0x00000000/8*4Ka,120*4Kg,3583*512Ka,4096*4Kg。
   驱动缺失/解析诊断记录也保留在 Research/Screen/Backup<UTC>，不将失败读写当作备份成功。
3. 实机应用区 0x8000 起 491520 字节，连续两次读取完全一致：
   Research/Screen/Backup20261102T065739Z/ScreenApplication.bin
   SHA256 5da95e4ac051fa2f64558fc48bf3d3501685b9c27b2e974d62dd3aa3a1db4895。
   实机包内 build Sep 6 2026 23:18:16，与云端 20:47:09 版本不同，不按云端地址直接修改。
   0x4AACC..0x7F000 全 FF；0x7F000 起已有其他数据，不能当作任意空闲区擦写。
4. 实机 Bootloader 0x0 起 32768 字节，连续两次读取完全一致：
   Research/Screen/Backup20261102T070811Z/ScreenBootloader.bin
   SHA256 3392e7e17bbb1ec414c586d1d0e82c892deaf4fd2ae227686bd207bb5d58fc40。
   未写 Bootloader。0x369A 检查 RAM 0x20000000 的 A5A5A5A5 标志进入 DFU。
   0x36B6 读取第二个保留 RAM 字；原应用 0x39558 也向 0x20000004 写入复位标志。
   Bootloader 0x367E 读取 GPIO 0x40041800 的 bit 6；实体按键/引脚对应还未确认。
5. 实机 task_lvgl 入口 0x3C5F8，0x3C608 调用原始 UI 初始化 0x11798。
   实机显示注册 0x2AEA8..0x2AEB0 将 480×360 写入 LVGL 显示配置。
   HID 320×320 仍是协议回报值，不能直接等同物理面板尺寸。
   原生对象、label、文字更新、style 设置、页面加载和 timer 函数已定位，见 NativeProfile.json。
   采用窄接口桥接；完整 LVGL 版本、SDK 和整个原厂源码仍未知。
6. 同一份 ScreenUi.c 编译为设备端 C 代码，约 1294 字节附加代码，放在 0x50000 页。
   标题 NEOS75 UI，正文 hellow world，设备定时器每秒更新 Running HH:MM:SS。
   另接入处理器故障返回 DFU 和 UI 线程超时保护，保留 RTX SysTick 的原中断上下文。
   指令级模拟通过，模拟代码和依赖不留在仓库；未在实机故意制造处理器异常。
7. 实际写入应用区 Payload 0x50000、Vector 0x8000、Hook 0x3C000 三个页，各 4096 字节。
